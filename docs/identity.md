# ID 체계 — 동/호 하나로 세 시스템을 잇는다

Kamailio(SIP) · Janus(WebRTC↔SIP) · websocket-relay(등록·푸시)가 같은 단말을
가리키는 방법입니다. **여기가 유일한 출처입니다** — 세 서비스의 문서는 이 문서를
가리키기만 합니다.

## 왜 필요한가

셋이 각자 ID 를 갖고 있었고, 그 사이를 **앱이 손으로 이었습니다.**
`rtc_mobiles.sip_user` 는 앱이 자유 문자열로 보내는 값이라, 안 보내면 그 단말은
착신 대상 조회에 걸리지 않습니다 — 오류도 나지 않고 조용히 0건입니다.
`services/kamailio/check-push.sh` 가 *"이 흐름에서 가장 자주 비어 있는 자리"* 라고
적어 둔 자리이고, 실제로 지금 등록된 단말 하나도 `sip_user` 가 `NULL` 입니다.

원인은 ID 하나에 두 가지 일을 시킨 것입니다. **착신 대상**(어느 집에 걸까)과
**인증 주체**(누구의 단말인가)는 다른 축인데, 동/호 하나로 둘 다 하려니 한 세대의
5대가 구분되지 않았습니다.

## 축은 셋이다

| 축 | 무엇을 가리키나 | 값 | 공유 범위 |
|---|---|---|---|
| 세대 | 사람이 누르는 번호 · 단말번호를 만드는 기준 | `01010805` (동4+호4) | 그 집 전부 |
| 단말 | 등록 · 인증 · 회수 · 감사 | `0101080501` (세대+순번2) | 단말 하나 |
| 세션 | 이 통화 | SIP `Call-ID` · relay `roomId` · Janus handle | 통화 하나 |

relay 는 이 셋을 이미 다 갖고 있습니다 — `address`(세대) · `uuid`(단말) ·
`roomId`(세션). 없던 것은 **SIP 쪽 표기**뿐입니다.

## 번호 형식

```
 0101 0805 01
 └동4┘└호4┘└순번2┘        101동 805호 1번 단말
```

- **숫자 10자리 고정.** 인터폰 키패드로 눌러야 하므로 특수문자를 쓸 수 없습니다.
  자릿수 자체에는 제한이 없어 10자리로 잡았습니다.
- **고정폭이어야 합니다.** `1동 101호`(`1`+`101`)와 `11동 01호`(`11`+`01`)가
  가변폭에서는 둘 다 `1101` 이 됩니다. 두 집에 같은 번호가 나가고 한 집은 남의
  전화를 받습니다. 거는 쪽이 뒤 두 자리를 붙이는 것도, 앞 8자리의 폭이 정해져
  있어야 자를 자리를 알 수 있습니다.
- **단지는 넣지 않습니다.** 단지마다 서버와 도메인이 다르고 서버 간 통화가 없으므로,
  단지를 가르는 일은 도메인이 이미 하고 있습니다. `complex_id` 는 **등록 절차에서만**
  씁니다 — 등록되지 않으면 어차피 통화가 되지 않습니다.

### 순번 대역

| 순번 | 무엇 | 누가 만드나 |
|---|---|---|
| `00` | 월패드 | `POST /register/complex_agents` 때 만든다. 이미 있으면 그대로 둔다 |
| `01`~`04` | 모바일 | relay 가 **승인 시점에** 배정한다 |
| `05`~`99` | 예약 | |

`libs/enrollment.ts` 의 `MAX_APPROVED_PER_HOME = 4` 가 `01~04` 와 맞습니다.
상한을 두 곳에 적지 말고 이 대역에서 유도합니다.

### 동/호 → 번호

`services/websocket-relay/src/libs/address.ts` 의 표기(`101B805U`)에서 유도합니다.

```
101B805U  →  동 "101" → "0101",  호 "805" → "0805"  →  01010805
1B101U    →  동 "1"   → "0001",  호 "101" → "0101"  →  00010101
```

왼쪽을 `0` 으로 채워 4자리로 맞춥니다. **숫자가 아닌 동/호는 번호를 가질 수
없습니다** — `ADDRESS_RE` 가 `[A-Za-z0-9-]{1,8}` 이라 `A동` 같은 값이 들어올 수
있는데, 그런 세대는 SIP 번호를 만들지 않고 WebRTC 초인종 경로만 씁니다
(그쪽은 `address` 로 도므로 영향이 없습니다). 5자리를 넘는 동/호도 같습니다.

## 어느 값이 어디에 사는가

| 자리 | 값 | 예 |
|---|---|---|
| 인터폰이 거는 RURI | **단말** 10자리 | `sip:0101080501@<단지도메인>` |
| `subscriber.username` | **단말** 10자리 | `0101080501` |
| 단말이 REGISTER 하는 AOR | **단말** 10자리 | `sip:0101080501@…` |
| Janus `register.username` | 단말 10자리 | `sip:0101080501@…` |
| Janus `register.authuser` | 단말 10자리 (같다) | `0101080501` |
| `rtc_mobiles.sip_user` | **단말** 10자리 | `0101080501` |
| `rtc_mobiles.address` | 세대 | `101B805U` |

Janus 의 `username` 과 `authuser` 를 **같게** 두는 것이 중요합니다.
`kamailio.cfg` 의 `auth_check("$fd","subscriber","1")` 은 flag `1` 이
"digest 사용자명 == To 사용자명" 을 강제하는데, 단말이 자기 ID 로 등록하면 이
검사가 그대로 통과합니다. 인증 설정을 손대지 않는 쪽이 안전합니다.

## 착신 — 퍼뜨리는 일은 **거는 쪽**이 한다

인터폰은 세대 8자리를 누르지만, **클라이언트가 뒤 두 자리를 붙여 보냅니다.**
그래서 서버가 받는 RURI 는 언제나 단말 10자리이고, 한 번의 INVITE 는 한 대를
가리킵니다. 여러 대를 울리는 것은 거는 쪽이 여러 번 거는 것으로 이룹니다.

```
인터폰 ──INVITE sip:0101080501@단지도메인──▶ Kamailio
  route[LOCATION]
    lookup("location")  성공 → 그 단말의 contact 로 relay      (깨어 있다)
                        실패 → t_newtran(); ts_store();        (자고 있다)
                               POST /sip-push {aor:"0101080501"}
                               183 Session Progress
  route[REGISTRAR]      그 단말이 깨어나 등록
    save("location"); ts_append("location", "$tu");   ← 붙들어 둔 INVITE 를 잇는다
```

### Kamailio 설정은 **바꾸지 않습니다**

번호 체계를 바꾸면서도 `kamailio.cfg` 를 손대지 않아도 되는 이유가 셋입니다.
셋 다 "단말이 자기 번호로 등록하고, 인터폰도 그 번호로 건다" 에서 나옵니다.

| 자리 | 왜 그대로 되는가 |
|---|---|
| `auth_check("$fd","subscriber","1")` (kamailio.cfg:949) | flag `1` 이 "digest 사용자명 == To 사용자명" 을 강제하는데, 단말이 자기 번호로 등록하므로 그대로 맞는다 |
| `ts_store()` (kamailio.cfg:841) | 인터폰이 건 RURI(단말번호)로 붙들어 둔다 |
| `ts_append("location","$tu")` (kamailio.cfg:793) | 등록의 To(단말번호)로 찾는다 — 위와 **같은 값**이라 맞물린다 |

세대 AOR 을 공유하는 안으로 갔다면 셋 다 고쳐야 했습니다 — 인증 flag 를 낮추고
소유 검사를 새로 넣고, `$(tU{s.substr,0,8})` 로 순번을 떼어야 했습니다.

### 대신 거는 쪽이 지는 몫

- **한 대가 받으면 나머지를 취소해야 합니다.** 다섯 개의 독립 트랜잭션이라 SIP
  포크와 달리 CANCEL 이 저절로 가지 않습니다. 거는 쪽이 보내야 합니다.
- **빈 자리로 걸면 480 이 옵니다.** 그 집에 두 대만 있으면 `03`·`04` 는
  `/sip-push` 가 `pushed: 0` 으로 답하고 Kamailio 가 480 으로 끝냅니다.
  오류가 아니라 정상입니다.

> `/sip-push` 는 **세대번호 8자리도** 받습니다 — 그러면 그 집 단말 전부가
> 대상이고 `missing:["02","04"]` 로 자리를 좁힐 수 있습니다. 나중에 퍼뜨리는
> 일을 서버로 옮길 때 쓰는 길이며, 지금 경로에서는 쓰이지 않습니다.

## 순번 배정 — 읽고-비었으면-쓰기로는 안 된다

관리자 둘이 같은 집을 동시에 승인하면 같은 번호를 둘에게 줍니다. 확실한 것은
**DB 제약 하나뿐**입니다.

- `UNIQUE (complex_id, address, sip_seq)` 를 건다. 경합하면 INSERT 가 실패하고,
  다음 빈 번호로 재시도한다.
- ⚠️ `schema/002-sip-user.sql` 에 *"UNIQUE 를 걸지 않는다 — 한 내선에 휴대폰·태블릿이
  함께 붙을 수 있다"* 고 적혀 있습니다. **그 전제가 이 설계에서 사라집니다.**
  한 내선 = 한 단말이 되므로 마이그레이션에서 뒤집어야 합니다.
- **`uuid` 로 기존 배정을 되찾습니다.** 앱을 지웠다 다시 깔 때마다 새 번호를 주면
  네 칸이 금세 찹니다.
- 단말을 지우면 번호를 반납합니다. 다음 승인이 그 자리를 씁니다.
- 비어 있는 **가장 작은** 번호를 줍니다.

## 앱이 바뀌는 것

| 지금 | 바뀐 뒤 |
|---|---|
| `/register/mobile` 에 `sip_user` 를 실어 보낸다 | **보내지 않는다.** 서버가 승인 시점에 배정한다 |
| SIP 비밀번호를 사람이 앱에 넣어 준다 | `/register/mobile` 응답의 `sip` 로 받는다 |
| Janus `register` 에 사람이 정한 내선 | 받은 단말번호로 등록한다 |

**자격은 푸시로 보내지 않습니다.** 승인 푸시에 비밀번호를 실으면 그 값이 구글을
지나갑니다. 앱은 승인을 확인하려고 어차피 다시 등록하므로, 그때 응답에 실어
주면 서버와 단말 사이에서 끝납니다 — 클라이언트 인증서를 같은 자리에서 내려주는
것과 같은 이유입니다(`schema/006-device-cert.sql` 의 *"요청할 때만 서명한다"*).

```jsonc
// POST /iot/register/mobile — 이미 승인된 단말의 응답
{ "result": "success", "status": "approved",
  "sip": { "user": "0101080501", "domain": "pluto.org", "password": "…" } }
```

`sip` 가 없으면 번호를 받기 전에 승인된 옛 단말이거나 번호를 만들 수 없는
세대입니다. 둘 다 예전처럼 동작합니다.

앱이 ID 를 정하는 길이 닫히면, 맨 앞에서 말한 실패 모드(`sip_user` 가 비어 조용히
착신 0건)가 구조적으로 사라집니다.

## 월패드 자리(`00`)

월패드도 같은 대역을 씁니다. 다만 두 가지가 모바일과 다릅니다.

- **번호를 저장하지 않습니다.** `rtc_homenet` 은 동/호를 갖고 있고 번호는 거기서
  계산되므로, 따로 적어 두면 두 값이 어긋날 수 있습니다. 지울 때도 같은 계산으로
  되찾습니다.
- **비밀번호를 돌리지 않습니다.** 월패드는 부팅할 때마다 등록을 부르는데
  (`/register/complex_agents` 는 upsert 입니다), 그때마다 새로 발급하면 이미
  등록해 둔 값이 매번 어긋납니다. 그래서 있으면 그대로 돌려줍니다
  (`libs/sipAccount.ts` 의 `ensure`).

자격은 등록 응답에 실려 옵니다 — 모바일과 같은 자리, 같은 방식입니다.

```jsonc
// POST /register/complex_agents
{ "result": "success",
  "sip": { "user": "0101080500", "domain": "pluto.org", "password": "…" } }
```

월패드가 SIP 를 쓰지 않는 배치라면 이 값을 무시하면 됩니다. 계정이 하나 남을
뿐이고 아무것도 강제하지 않습니다.

### 시험용 세대 — `9999`동 `9999`호

Janus 하니스(`test-harness/*.html` · `verify-call.sh --run` · `verify-bridge.sh` ·
대시보드의 '시험 통화')는 **`9999999901`~`04`** 를 씁니다. 이 체계 밖의 이름
(`2001~2004`)을 쓰던 것을 옮긴 것입니다.

체계 안에 두는 편이 나은 이유는, 시험 계정이 체계 밖에 있으면 "이 번호는 무엇
인가" 를 매번 따로 설명해야 하고 규칙을 벗어난 예외로 굳기 때문입니다. 실재하지
않는 동/호를 골라 두면 그런 설명 없이도 진짜 세대와 부딪히지 않습니다 —
**실재하는 세대의 번호로 시험하면 그 집 폰이 울립니다.**

옛 시험 계정 `0010200601~04`(= `0010`동 `2006`호)도 지웠습니다.

## 적용 순서

1. ~~**relay**~~ ✅ — 순번 배정(`schema/007-sip-number.sql` · `libs/sipNumber.ts`),
   승인 시 `subscriber` 계정 발급(`libs/sipAccount.ts`), 단말을 지울 때 계정 회수,
   `/register/mobile` 응답의 `sip`, `/sip-push` 의 세대번호와 `missing`.
   Kamailio 를 건드리지 않으므로 **착신 동작은 지금 그대로**입니다 — 인터폰이
   아직 단말번호로 걸고 있어도 `sip_user = ?` 정확 일치가 그대로 남아 있습니다.
2. ~~**Kamailio**~~ ✅ — **바꿀 것이 없습니다.** 위의 '설정은 바꾸지 않습니다' 를
   보세요. 퍼뜨리는 일을 나중에 서버로 옮기게 되면 그때 `route[LOCATION]` 에
   세대 확장을 넣습니다.
3. **앱·월패드** — `sip_user` 를 보내지 않고, 등록 응답의 `sip` 로 Janus 또는
   SIP 스택에 등록합니다.
