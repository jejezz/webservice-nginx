# 되돌리기 — 잘못 넣었을 때, 그리고 다시 하고 싶을 때

구축 마법사를 따라가다 값을 잘못 넣었을 때 어디까지 되돌아갈 수 있는지를
모은 문서입니다. 지금까지 이 정보는 각 스크립트의 `--remove`, `pm2/README.md`,
`setup_mariadb.sh` 의 헤더 주석에 흩어져 있었습니다. 정작 필요한 순간에는
찾아다닐 여유가 없습니다.

## 먼저 — 마법사는 아무것도 바꾸지 않습니다

이것을 모르면 없는 걱정을 하게 됩니다. 마법사가 하는 일은 **점검 스크립트를
읽기 모드로 돌려 결과를 보여 주는 것**뿐입니다. `--apply` 를 실행하지 않고
sudo 도 부르지 않습니다 (`services/manager/server/src/services/setup.js` 의
'경계' 주석).

마법사가 파일을 쓰는 곳은 **둘뿐**입니다.

| 파일 | 무엇 |
|---|---|
| `services/<서비스>/settings.ini` | 폼에 넣은 값 |
| `services/manager/setup-attest.json` | 사람만 확인할 수 있는 것의 확인 기록 |

진행률은 저장조차 하지 않습니다 — 열 때마다 점검을 다시 돌려 계산합니다.
그래서 **마법사를 다시 여는 것은 운영 중인 장비에서도 안전합니다.** 화면을
새로 고치는 것과 같습니다.

실제로 장비를 바꾸는 것은 전부 **사람이 터미널에서 치는 `--apply`** 입니다.

## 세 층으로 나누어 보세요

되돌릴 수 있느냐는 "어느 층까지 갔느냐" 로 갈립니다.

| 층 | 무엇이 | 잘못 넣고 적용하면 | 고쳐서 다시 하면 |
|---|---|---|---|
| ① 값 | `settings.ini` | 아무 일도 안 일어남 | 고치면 끝 |
| ② 설정 파일 | `kamailio-local.cfg` · `.jcfg` · nginx | 그 파일이 통째로 다시 쓰임 | **수렴합니다** |
| ③ 만들어진 것 | DB · 계정 · pm2 목록 · systemd · 인증서 | 남습니다 | **수렴하지 않습니다** |

### ① 값 — 걱정할 것이 없습니다

`settings.ini` 에 무엇을 넣어도 그것만으로는 아무 일도 일어나지 않습니다.
마지막으로 적용한 값은 옆의 `.applied-settings` 에 따로 적혀 있고, 둘이
다르면 점검이 '아직 반영되지 않았습니다' 로 알려 줍니다.

**그 반대도 성립합니다 — 값을 고쳐 놓고 `--apply` 를 잊으면 조용히 어긋난 채
돕니다.** 실제로 그런 적이 있습니다. `sip_push_url` 을 `https` 에서 `http` 로
고쳐 두고 적용하지 않아, 도는 Kamailio 는 계속 `https` 로 푸시를 보내려다
실패했습니다. 릴레이는 평문으로만 듣고 있었으므로 착신이 통째로 나가지
않았고, 로그도 조용했습니다.

그러니 마법사를 열었을 때 `[--]` 가 보이면 그것부터 보십시오.

### ② 설정 파일 — 다시 `--apply` 하면 됩니다

`install.sh --apply` 는 템플릿에서 **파일을 통째로 다시 씁니다.** 이전 것을
`.bak.<시각>` 으로 백업하고, 치환되지 않은 자리(`__FOO__`)가 남으면 파일을
지우고 멈춥니다 — 반쯤 만들어진 설정으로 서비스를 재시작하지 않습니다.

그래서 **잘못된 값으로 한 번 적용했더라도 처음부터 다시 할 필요가 없습니다.**
값을 고치고 다시 `--apply` 하면 그대로 돌아옵니다.

```bash
sudo ./services/kamailio/install.sh          # 점검만
sudo ./services/kamailio/install.sh --apply  # 다시 씀
sudo ./services/kamailio/install.sh --remove # 걷어내고 기본 상태로
```

`services/janus/install.sh` 도 같은 세 모드입니다.

> `--apply` 가 덮는 것 중에 **손으로 고쳐 둔 줄**이 있을 수 있습니다. 점검이
> "설치본에만 있는 줄 N개" 로 알려 주지만 내용은 찍지 않습니다(비밀이 섞일 수
> 있어서). 덮기 전에 직접 보십시오:
>
> ```bash
> sudo diff /etc/kamailio/kamailio.cfg services/kamailio/kamailio.cfg
> ```

### ③ 만들어진 것 — 여기부터는 손이 갑니다

**전부 지우고 처음부터 다시 하는 한 방은 없습니다.** 설계상 만들지 않기로 한
것입니다(`docs/setup-wizard.md` 의 '만들지 않는 것'). 되돌리기는 각 스크립트가
자기 몫만 갖습니다.

#### 데이터베이스

`database/setup_mariadb.sh` 는 **추가와 갱신만 합니다. `database.ini` 에 없는
데이터베이스나 사용자를 삭제하지 않습니다** (스크립트 헤더에 그렇게 적혀
있습니다). 이것이 뜻하는 바가 둘입니다.

- **스키마가 이미 만들어진 상태에서 다시 돌리는 것은 안전합니다.** 그게 설계
  목표입니다. 스키마 파일도 여러 번 실행해도 되도록 씁니다
  (`CREATE TABLE IF NOT EXISTS`)
- **잘못 만든 것은 저절로 사라지지 않습니다.** DB 이름이나 사용자를 잘못 넣고
  적용했다면 그 DB 는 그대로 남습니다. 지우려면 손으로 `DROP` 해야 합니다

무엇이 바뀔지 먼저 보려면:

```bash
sudo database/setup_mariadb.sh --dry-run
```

#### pm2

여기가 가장 헷갈리는 자리입니다. **선언과 재부팅 복원 목록이 별개입니다.**

- 선언 — `services/*/pm2-conf/*.ini` 를 `pm2/ecosystem.config.js` 가 모읍니다
- 복원 목록 — 마지막 `pm2 save` 시점의 스냅샷

선언에서 앱을 빼도 **이미 `save` 된 목록은 재부팅 때 되살아납니다.** 실제로
지우려면 둘 다 해야 합니다:

```bash
pm2 delete <이름> && pm2 save
```

셋이 어긋나 있는지는 이걸로 봅니다:

```bash
node pm2/ecosystem.config.js --check
```

#### systemd

Kamailio 와 Janus 는 pm2 가 아니라 systemd 가 띄웁니다. 각자의
`install.sh --remove` 가 설정을 백업해 걷어내고 재시작합니다. 서비스를 잠시
내리기만 할 거라면 `README.md` 의 '전부 멈추기' 절을 보십시오.

#### 인증서

`certbot` 이 만든 `renewal/<이름>.conf` 는 인증서가 만료돼도 남습니다. 그래서
`tls_mode` 를 `auto` 로 둔 채 사설로 강등하면 판정이 계속 `public` 입니다.
강등은 `private` 로 못박아야 하고, 되올라갈 때 그것을 되돌리는 것을 잊으면
발급이 성공해도 계속 사설을 내밉니다. `nginx/cert-status.sh` 의 `warn`
하나로만 보입니다.

#### 마법사의 확인 기록

사람이 눈으로 확인한 단계(`manualOnly`)의 기록은 지울 수 있습니다.

```
DELETE /manager/api/setup/attest/:stepId
```

터미널에서 되돌려 놓고 이 기록을 지우지 않으면 화면은 "완료" 로 남습니다.

## 운영 중인 장비에서는 시험이 되지 않습니다

마지막으로, 자주 헷갈리는 것 하나. **이미 설치된 장비에서 마법사를 끝까지
돌려 전부 초록이 나와도 그것은 아무것도 증명하지 않습니다.** 새 소스가 옳아서가
아니라 예전에 이미 해 놨기 때문입니다 (`docs/clean-install-test.md` 첫머리).

재현성을 보려면 빈 장비나 VM 이어야 합니다. 운영 중인 장비에서 얻을 수 있는
것은 **어긋남의 발견** 쪽입니다 — 위의 `sip_push_url` 처럼, 값과 설치본이
갈라진 자리를 점검이 짚어 줍니다. 그것대로 값어치가 있으니 마법사를 열어
`[--]` 를 훑어보는 일은 정기적으로 할 만합니다.
